not configured — the site works fully without it; the “Enhance with AI” button only appears once this is set up.

To enable, add these lines to /opt/netai/.env and restart (sudo systemctl restart netai):

# OpenAI (or any OpenAI-compatible provider)
AI_PROVIDER=openai
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini

# — or Anthropic —
# AI_PROVIDER=anthropic
# ANTHROPIC_API_KEY=sk-ant-...
# ANTHROPIC_MODEL=claude-sonnet-4-20250514

Fully local (no cloud, no key needed) with Ollama:

# on this server:  curl -fsSL https://ollama.com/install.sh | sh
# ollama pull llama3.2-vision          # vision (config generator)
# ollama pull llama3.2                 # text (summary enhancement) - optional
AI_PROVIDER=custom
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_API_KEY=ollama
OPENAI_VISION_MODEL=llama3.2-vision
OPENAI_MODEL=llama3.2

Everything then runs on this server - no data leaves the network. Vision models need roughly 8-16 GB RAM (GPU speeds it up a lot); on CPU-only expect around a minute per diagram.

Free cloud tiers (no credit card) - also OpenAI-compatible:

# Google Gemini free tier (vision-capable, ~5-15 req/min)
# get a key at aistudio.google.com - no card needed
AI_PROVIDER=custom
OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
OPENAI_API_KEY=YOUR-GEMINI-KEY
OPENAI_VISION_MODEL=gemini-2.5-flash
OPENAI_MODEL=gemini-2.5-flash

# Groq free tier (very fast, text models)
# key at console.groq.com
# AI_PROVIDER=custom
# OPENAI_BASE_URL=https://api.groq.com/openai/v1
# OPENAI_API_KEY=gsk_...
# OPENAI_MODEL=llama-3.3-70b-versatile

Privacy warning: on free cloud tiers your uploads (including topology diagrams - i.e. maps of your network) are processed by the provider and may be used to improve their models. For real infrastructure data prefer the local Ollama option; free tiers are fine for testing, demos and non-sensitive summaries.

Cloud keys stay in the .env file (root-only) and are never stored in the database or shown in the UI.
